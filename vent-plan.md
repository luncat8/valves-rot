# Vent mode: random-map pressure regulation

## Goal

Add a one- or two-seat mode to the shared prototype. It uses the same random valve
field as the other modes, with the same random distribution of valve types. At
setup, build a usable gas route to each player's collector by orienting existing
on-map valves; do not replace those routes with straight pipes or change valve
types to make the task easier. Each collector is exactly a
`hollow single · direction · random°` valve. Players control only their own
source/vent mouths, never valves. `5%` of valves continue their seeded automatic
rotation. Each player holds the collector's pressure within a target range.

The mode keeps the existing file-friendly runtime, classic script loading,
fixed-step gas model and shared geometry. No path-search or evaluation work runs
in the frame hot path.

## Field and route setup

- Keep the map generated by `G.createLayout(seed)`. Preserve every existing
  valve's type and chamber except the one collector cell per seat. Orient only
  route valves required for pressure connectivity; those valves remain ordinary
  random valves and are not locked against the mode's `5%` auto-rotation.
- Pick a collector location and a random quarter-turn for its single port. Its
  adjacent junction must use an existing tee or cross valve. Route one source
  from the bottom boundary and one vent from the top boundary to that junction.
  The junction connects both routes and the collector port.
- Route search may rotate a candidate valve but may not alter its type. For each
  route cell, select an orientation that connects the incoming and outgoing
  world ports. Keep the other field cells untouched. If a second seat shares an
  existing route cell, preserve that cell's established orientation when
  searching so the earlier route remains usable.
- Give each seat one owned high-pressure source mouth and one owned low-pressure
  vent mouth at the route's boundary endpoints. Clear other mouths on entry.
  Only the owning human can press these two mouths; a bot may drive its own pair.
- Drain grains and enable the grid-gas backend. Keep the collector in the same
  automatic rotation pool as the rest of the map so the mode preserves the full
  `5%` rotating-valve selection.
- Save each modified cell's original valve type, world orientation, chamber,
  tint, lock and goal owner. Restore those cells and the inlet bands on exit; do
  not rebuild or simplify the field on teardown.

## Pressure target and scoring

Measure each collector's reachable pressure with its own source and vent while
leaving other seats' controls as-is. Fit a target band inside that measured
range. A seat scores for holding its collector within the band continuously for
`4 s`; narrower bands earn more. After scoring, move the next band a small step
from the prior target. Count one failure when pressure strays far enough outside
the band, then re-arm after it recovers. A bot can automate the same two-mouth
policy available to a person; it does not operate any valve.

## Seats and input

- Vent mode supports one or two seats because mouths pin a shared gas field and
  additional players would be dominated by its pressure average.
- The existing roster and per-seat human/bot controls remain available.
- In Vent mode `canTurn` rejects every valve, including automatic route valves;
  automatic rotation remains simulation behavior only.
- Clicking a seat row selects its collector. The field gauge shows current
  pressure, the target tag shows the band and the hold arc shows progress.

## Validation

`node experiments/vent-fixtures.cjs` checks the collector type and random
orientation, preserved map valve types, route reachability and mouth ownership,
`5%` auto-rotation, player input restrictions, deterministic setup, band fit,
seat add/remove and exact restoration. `node experiments/vent-balance.cjs`
surveys one- and two-seat route coverage, pressure reach and teardown across
seeds. `node experiments/render-smoke.cjs` checks mode UI, input ownership and
restore. The other game, pressure and geometry fixtures protect shared modes.
